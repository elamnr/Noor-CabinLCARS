# Bridgeline Console (Retro House LCARS dashboards)

Source of truth for the four LCARS-style Home Assistant consoles. Every file in this folder is a project doc; update the changed files here after each edit session.

## Current deployment (2026-11-06, build v29)
- Auto-deploy (2026-11-06): push to `main` touching `console/` → GitHub Action builds, runs `tests/ci.js`, force-pushes `bridgeline-bedroom-console.js`, `bridgeline-loader.js`, `bridgeline-version.json` to the `deploy` branch, then POSTs `{"sha"}` to the HA webhook (`HA_WEBHOOK_URL` repo secret). Other branches never deploy; designs are previewed in chat first and pushed only on request
- HA side: `automation.bridgeline_console_deploy` (webhook trigger, POST, not local-only, queued) calls `shell_command.bridgeline_deploy` (`!secret bridgeline_deploy_cmd`; template in `deploy/secrets.example.yaml`; fine-grained PAT, Noor-LCARS only, Contents read-only), checks the announced sha appears in the downloaded version file (one retry after 30 s), notifies success/failure (notification ids `bridgeline_deploy_ok` / `bridgeline_deploy_failed`). Downloads go to `.tmp` and are moved into place only after all three succeed
- Bundle: `/config/www/bridgeline-bedroom-console.js` (one file serves all rooms; filename kept to avoid HA's cached-404 on new /local/ paths)
- Lovelace resource id `015ac05d284f4f5194d32a22f7f03a03` = `/local/bridgeline-loader.js` (module) since 2026-11-06, after the first webhook deploy (commit 9e277e6) was verified end to end. The loader fetches `bridgeline-version.json` uncached and imports the bundle with `?v=<sha>`; no more `?v=` bumps. Devices that still have the old `?v=29` resource cached need one hard refresh to switch to the loader
- Card tags: `custom:bridgeline-bedroom-console` (bedroom default) and `custom:bridgeline-console` with `room: bedroom | office | entry | house`
- Dashboards (panel view, one card each):
  - `bedroom-console` → bridgeline-bedroom-console
  - `office-console` → bridgeline-console room: office
  - `entry-console` → bridgeline-console room: entry
  - `house-console` → bridgeline-console room: house
  - `kitchen-console` → bridgeline-console room: kitchen (TV, extended desktop; replaces `kitchen-display`)
- Original Lovelace dashboards left untouched: bedroom-dashboard, office-tablet, basement-entry, surface-dashboard

## Build
Versions used: preact 10.29.8, @preact/signals 1.3.4 (signals-core 1.14.5), esbuild 0.28.2, Playwright 1.63.0 (dev), Node 22.

```
npm ci
node build.mjs
node tests/ci.js     # deploy gate: all rooms/pages, kitchen modes, card in every room
```
Outputs in `dist/` (not committed): `bridgeline-bedroom-console.js` (HA card) and standalone `<room>-console.html` (simulation previews; `?room=` overrides, kitchen `?kmode=calendar|camera`).
`src/card.css.txt` is generated by build.mjs from the CSS files; do not edit it.
Design tokens (`colors.css`, `typography.css`, `spacing.css`) are copied from the Bridgeline design system artifact.
`loader/bridgeline-loader.js` is the Lovelace resource loader; `deploy/secrets.example.yaml` the HA download command template.

- Office VEHICLES page (v41): `vehicles` + `vehicleCompact: true`; the nav page renders `CompactVehiclesPage` (the entry tablet's compact view, no CLOSE); its FULL DISPLAY swaps in the master systems display and that display's CLOSE returns to the compact view
- Office blinds: no group; console drives Left/Right/Large together, skipping offline units
- Office Main: TODAY agenda only; Schedule page: 7 days; calendar blocklist kept from original card
- Offline devices render solid red
- Agenda rows: gold + blinking countdown in the 5 min before start, teal 'NOW • n MIN LEFT' while running; 'event' chirp once per event at start time (rooms with a calendar; respects AUDIO OFF; all-day events excluded)
- SETTINGS footer button (v31) replaces SOUNDS: panel with tabs DISPLAYS and SOUND LIBRARY (old sounds panel content). DISPLAYS: THIS CONSOLE (running BUILD vs deployed `bridgeline-version.json`, local RELOAD), KITCHEN DISPLAY (presses `input_button.bridgeline_reload_kitchen`), ALL CONSOLES (presses `input_button.bridgeline_reload_all`). AUDIO ON/OFF stays in the footer. Intended home for future universal console settings
- Remote reload (v31): `ReloadWatch` in every console (and the kitchen) records the reload helpers' state on load and reloads the page 0.5-3.5 s after a later press (`_all` everywhere, `_<room>` for that room; only `_kitchen` exists). The deploy automation presses `_all` after every successful deploy, so consoles running v31+ update themselves
- Sound Library (now the SETTINGS > SOUND LIBRARY tab): one shared set for all tablets, stored in HA local media `bridgeline-sounds/` as `<slot>--<epoch ms>.<ext>`; newest file per slot wins, older copies deleted on upload. Upload/reset need an HA admin user (media_source upload API + `media_source/local_source/remove`); playback via `media_source/browse_media` + `resolve_media` works for any user. Tablets resync every 5 min, on wake, and on opening the panel. Files ≤2 MB, ≤10 s, decoded locally to validate; loudness auto-levelled (RMS target 0.12, peak ≤0.9). Per-tablet IndexedDB storage and FILE VOL slider removed (v14). 11 slots: tap, nav, on, off, command, slide, arm, dooralarm, event, alert, fault
- House Main: 16-button ZONES grid (7 zones, Climate, Garage, Doors, 4 Find My buttons pressing input_button.find_tricorder / find_katie_s_iphone / find_orion_s_ipad / find_work_ipad (handled by automation.find_my_ping_device), 2 UNASSIGNED placeholders SP-01..02)
- Entry Main: compact Atmospherics (4 stats, no meters) and Illumination as a single Chandelier toggle; detail stays on ILLUMINATION/WEATHER pages
- Narrow screens (≤760 px): left nav keeps vertical labels (rotated, 13 px) instead of hiding them; arm 34 px
- House CLIMATE page (`climateForecast: true` in rooms.js): OUTDOOR panel compacted (small readout, 4-stat row) with NEXT HOURS (8 h) and FORECAST (6 days) below, same HourStrip/DayList components as the entry WEATHER page. Source switched to NWS (v19)
- Weather source (entry + house): `weather.nws_retrohouse`, National Weather Service integration added 2026-10-31 (config entry 01M699MFT4DV0HMKKCMWSA5F28, station KSTP, HA home coordinates, API key string `retro-house-home-assistant`, no email). NWS offers hourly + twice_daily only: the console builds daily rows from day/night pairs (high = daytime, low = following night, rain % = max of the pair). NWS current state lacks dew point, cloud and UV: dew point falls back to the first hourly period; CLOUD and UV INDEX tiles become RAIN CHANCE (next hour) and VISIBILITY. met.no `weather.forecast_retrohouse` left in place (original Lovelace dashboards)
- Log Cabin thermostat excluded from house console (cabin out of scope)
- Big temperature readouts (weather, climate): line-height 1, vertically centred on the icon/side readings, 10 px bottom padding
- Weather icons and stepped colour scales are a deliberate deviation from the design system (no icons/gradients)

- Red = open door/window/frunk/trunk; cyan = charging (glowing pack outline, port, battery readout, STOP CHARGE)
- Asleep: header 'ASLEEP • LAST KNOWN', image dimmed; no data: 'NO DATA', controls grey
- Readouts (v32): TEMPERATURE | LOCATION (tap = map) | HV BATTERY | CHARGE (wide). Tire pressures moved to SYSTEM DETAILS > TIRES; any tire pressure warning shows in the header status. Tire leader lines removed
